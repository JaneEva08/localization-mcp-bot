## 1. Задание

Собрать небольшой MCP-проект на основе урока, адаптировать его под свою предметную область, расширить функции и протестировать Telegram-бота. Для сдачи подготовить рабочий код сервера и бота, короткое описание и подтверждение работы.

## 2. Что я сделала

Я адаптировала проект под свою рабочую задачу — проверку игровой локализации. В рабочем Excel есть русский перевод, который загружается в игру, исходный китайский текст и служебные атрибуты. Бот помогает быстро найти оригинал по переводу и наоборот, а также определить код предмета по названию или описанию.

Сервер и SQLite работают локально. Telegram служит интерфейсом. Для обычных фраз используется OpenAI-совместимый API: модель выбирает MCP-инструмент, приложение выполняет поиск и показывает данные без перефразирования. Явные команды работают без вызова модели.

Код подготовлен с помощью ИИ. Предметная область, правила полей и поиска определены мной; проверка в Telegram выполнена на рабочем локпаке.

## 3. Как устроен проект

```text
Excel, лист RUS+CHN
        ↓ import_excel.py
локальная SQLite
        ↑
MCP-сервер: четыре инструмента чтения
        ↑ Streamable HTTP
Telegram-бот ↔ модель (выбор инструмента для обычной фразы)
        ↓
перевод, оригинал, код и атрибуты из базы
```

| Компонент | Реализация |
|---|---|
| Язык | Python 3.12 |
| Импорт Excel | openpyxl, потоковое чтение |
| Хранилище | SQLite; 699 154 записи на локальной проверке |
| Протокол | официальный MCP Python SDK 1.30.0, Streamable HTTP |
| Telegram | aiogram 3 |
| LLM-клиент | AsyncOpenAI, Chat Completions function calling |
| Реальный провайдер и модель | aiprimetech.io, gpt-6-luna |
| Выдача | прямое форматирование результата базы, без генерации перевода |
| Доступ | один владелец по Telegram ID из локального .env |

### Поля Excel

Используется **только лист RUS+CHN**.

| Поле | Назначение |
|---|---|
| Id | имя исходной игровой таблицы |
| IsClient | признак клиентской таблицы |
| Name | идентификатор строки локализации |
| ColName | атрибут: название, описание и т. д. |
| TranslateTextJD | перевод, загружаемый в игру |
| NeedTranslateTextJD_CHN | исходный китайский текст |
| NeedTranslateTextJD | сохраняется отдельно, не подменяет игровой перевод |

NeedTranslateTextHJ и TranslateTextHJ исключены. Дополнительно сохраняются имя книги, SHA-256 импортированной версии, дата импорта и номер строки Excel.

### Инструменты

| MCP-инструмент | Что делает |
|---|---|
| search_russian | ищет в игровом русском переводе, возвращает китайский оригинал и атрибуты |
| search_chinese | ищет в китайском оригинале, возвращает русский перевод и атрибуты |
| find_item | находит код по названию или описанию; при неопределённом способе уточняет его |
| get_item | находит название и описание по коду для выдачи |

Для предметов область поиска ограничена:
- название: таблица CommonItem.txt, ColName=Name;
- описание: таблица CommonItemTips.txt, ColName=Tips;
- связь названия и описания: одинаковое значение столбца Name;
- код для выдачи: Name / 1000, без округления; обратный поиск: код × 1000.

Поиск сначала проверяет точное совпадение без учёта регистра. Если его нет — ищет по части текста. Дубли не скрываются. На странице до пяти найденных записей; связанные описания выводятся вместе с ними. Ответы оформлены полями через двоеточие.

## 4. Чем отличается от примера урока и почему

| В уроке | В моём проекте | Зачем |
|---|---|---|
| Каталог тестовых товаров | Импорт существующего Excel локализации | Решение реальной QA-задачи |
| Поиск товаров по имени | Поиск между русским и китайским текстом | Проверка соответствия оригинала и перевода |
| Добавление товара, калькулятор | Четыре инструмента чтения локализации | Для выбранной задачи не требуется менять данные |
| Простой список | Точное совпадение, подстрока, атрибуты и номер Excel | Быстро вернуться к нужной записи |
| Поиск по ID как доработка | Связь двух таблиц и код Name / 1000 | Получить именно код предмета для выдачи |
| Учебный HTTP-интерфейс | Официальный MCP SDK и реальный MCP-клиент | Стандартные initialize, tools/list и tools/call |
| Ответ модели | Текст базы выводится приложением | Не исказить перевод, теги или числовые ID |

Калькулятор и изменение каталога из товарного примера не переносились: домашнее задание допускает свою предметную область и расширения. В качестве расширений реализованы импорт Excel, обратный поиск, связь названия с описанием, расчёт кода и уточнение запроса.

## 6. Автоматические проверки

Команда:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

**20 тестов прошли:**
- 19 проверок импорта, поисков и клиентской логики: выбранный лист, исключение HJ, оба направления, регистр, буквальные спецсимволы, пустой перевод, дубли, предметные таблицы, связь пары, код без округления, неверные параметры, пагинация, сохранность прежней базы при ошибке импорта, владелец и длинные сообщения;
- 1 интеграционная проверка с отдельным настоящим HTTP MCP-сервером: initialize, обнаружение инструментов, все четыре инструмента, оба режима поиска предмета, уточнение и ошибка неверного кода.

В unit-тесте маршрутизации ответ LLM подставной. Отдельно выполнен реальный тест function calling у провайдера, а затем — пользовательские Telegram-сценарии выше. Рабочая SQLite прошла quick_check: ok.

## 7. Выводы

1. MCP позволил отделить поиск по данным от Telegram-интерфейса и выбора действия моделью. Набор инструментов бот получает у сервера.
2. Для такой задачи важнее точное сохранение исходных строк, чем генерация ответа. Игровые теги и цветовые коды остаются в тексте.
3. Одно русское название может соответствовать нескольким предметам или другим таблицам. Поэтому нужно показывать атрибуты, коды и все найденные варианты.
4. Одно китайское выражение может иметь разные русские переводы. Бот помогает находить такие случаи, но сам не решает, являются ли они ошибкой локализации.
5. ID строки, код предмета и номер Excel — разные значения. Их разделение и правило Name / 1000 проверены на реальном примере.

## 8. Ограничения и что не проверяла вручную

- Нажатие «Ещё» и /next после выдачи: пагинация проверена автоматически; на скриншотах видна кнопка, но её нажатие не подтверждено.
- Пустой перевод и неверный код проверены автоматически, но не отдельным ручным Telegram-прогоном. /reset и недоступность сервера в Telegram вручную не проверялись; отдельных автоматических тестов этих обработчиков тоже нет.
- Нет нечёткого поиска и поиска опечаток. При наличии точных совпадений подстрочные дополнительно не выдаются.
- Новый импорт заменяет активную базу. Перед ним нужно остановить сервер и бота. Номер Excel действителен для импортированной версии книги.
- Бот не исправляет переводы и не выдаёт предметы в игре.
- Работает на локальном ПК: компьютер и оба процесса должны быть включены, для Telegram и модели нужен интернет.
- Доступ редактора отложен за пределы ДЗ.

## 9. Запуск и проверка без рабочего локпака

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe make_demo.py
```

В .env заполнить свои TELEGRAM_API_TOKEN и OWNER_TELEGRAM_ID; для обычных фраз — OPENAI_API_KEY, OPENAI_MODEL и при необходимости OPENAI_BASE_URL. Для демо указать LOCALIZATION_DB=data/demo.db.

В первом терминале:

```powershell
.\.venv\Scripts\python.exe -m mcp_server.server
```

Во втором:

```powershell
.\.venv\Scripts\python.exe -m telegram_bot.bot
```

На вымышленных данных: /ru Лунный ключ, /zh 月亮钥匙, /item_name Лунный ключ, /item_desc Открывает лунные врата, /id 12. Полный запуск описан в [README.md](README.md).
